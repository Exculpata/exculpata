# Generated-claim evaluation (R1b)

This portable harness measures misleading claims and citation errors against a
frozen synthetic challenge set. It supports [issue #109](https://github.com/Exculpata/exculpata/issues/109).
It does not change model defaults, verification rules, source bytes, saved citation
basis, authorization, storage, or review policy. No migration or restore is needed.

The harness reuses production `EvidenceItem`, prompts, generation adapters,
`verify_original_claim`, `GroundedGenerationService._verify`, and the additional
original-span predicate used by recorded context. Like the existing model-portfolio
gold suite, it uses fixed evidence packets to isolate generation from retrieval.
The foundation policy benchmarks, discovery gold, workflow-quality evaluator,
served answer regressions and installed acceptance remain separate.

## Frozen challenge and rubric

[`benchmarks/r1b-claims-v2.json`](../benchmarks/r1b-claims-v2.json) contains 11 cases
and 27 single-claim candidates: 13 faithful controls and 14 invalid candidates.
Its canonical JSON SHA-256 is
`dd64595bb51c83c395616988ca51f77701dee6d59136da1a2912c23afe42691a`.
Source text is UTF-8 with no appended newline; source digests, stable synthetic
document IDs, labels and locators are frozen with the questions and rubric.
V2 supersedes the draft v1 rubric to make generation error units explicitly raw
claim occurrences, including limitations and duplicates. V1 remains in Git history
at `e782c3eb90112fa9044c294942de293c5c819ab2`; source bytes, source IDs, candidates
and reference labels are unchanged. No real-model evaluation used either version
while preparing this correction. V2 refuses v1 captures rather than silently
assigning them a changed rubric.
The fixtures were authored for this test, not generated by an evaluated model.
Their reference labels require human acceptance before any release decision.

Challenges cover actors, approval/rejection, numbers, dates, negation, uncertainty,
unrelated combined facts, quotes, missing/unknown/unrelated citations and attribution
loss. Numbers and dates include wrong associations using values already present in
the source. Faithful paraphrases and a faithful multi-source conjunction prevent a
reject-everything policy from appearing successful. A nested allegation tests an
exact substring that misleadingly drops its attribution: span matching is not truth.

Semantic validity and citation validity are separate booleans. A changed fact may
still point to the intended source, while a true fact can cite the wrong record.
Every material error fails that claim; no partial credit. Application response
rejection counts as rejection of every candidate, even if a candidate alone passes
the text predicate. The exact-span path is an isolated predicate comparison, not
execution of the full recorded-context workflow.

The diagnostic targets (zero false acceptance and zero false rejection) were fixed
with the suite. They are deliberately not release thresholds. **Release quality
thresholds and representative sampling must be approved before a real evaluation.**
Changing fixtures, rubric, labels or targets requires a new version and fingerprint;
never relabel a case to match the observed verifier.

## Offline deterministic probes

From the repository, with its development dependencies installed:

```console
PYTHONPATH=src python scripts/evaluate-claims.py probes --output /tmp/r1b-probes.json
PYTHONPATH=src python -m pytest -q tests/test_claim_evaluation.py
```

Probes make no model/network calls. The receipt reports full code commit,
dirty-tree state, implementation hashes, OS, architecture, Python version, fixture
fingerprint, configured generator/embedding/reranker revisions and licenses, and
all case-level outputs and verdicts. It omits machine names and local paths.
Evaluation JSON inputs and receipt files use UTF-8 on every platform.
All model execution and offline-model readiness remain explicitly unexercised.
Exit zero means the harness completed, not that quality targets passed; inspect
the metrics. Existing output files are never overwritten.

At the implementation baseline `a33d93b5302fc0f726f361ae2e3341883a4bdd77`, the
ordinary verifier accepted 8/14 invalid candidates and rejected 0/13 faithful
candidates. The exact-span predicate accepted 1/14 invalid candidates and rejected
4/13 faithful candidates. These are deterministic challenge-set results, **not
generation error rates, production error rates or model acceptance**. Later
verifier changes may legitimately change these numbers and their regression
expectations; do not change the frozen ground-truth labels.

## Real-model capture on a separately authorized isolated target

This change does not execute models or operate an existing installation. An
operator can run the capture after arranging the pinned model and its local
endpoint. The command neither downloads nor starts services. Supply an external
runtime-profile JSON with exactly these fields (replace illustrative values with
actual inspected evidence; an invented digest is not evidence):

```json
{
  "runtime_name": "vLLM",
  "runtime_version": "record actual version",
  "accelerator": "record actual device or CPU",
  "accelerator_memory_gib": 0,
  "driver": "record actual driver or none",
  "model_artifact_sha256": "record 64 lowercase hex characters",
  "upstream_model_id": "Qwen/Qwen3.5-4B",
  "upstream_revision": "851bf6e806efd8d0a36b00ddf55e13ccb7b8cd0a",
  "license": "Apache-2.0",
  "offline_readiness": "not_exercised",
  "offline_evidence_sha256": null
}
```

Use the selected profile's exact upstream pin/license from `config/models.json`;
the harness rejects a conflicting declaration. For Ollama, use its immutable tag
digest as the artifact digest and retain the conversion/upstream linkage evidence.
For vLLM, retain the staged inventory digest and launch evidence connecting the
served alias, exact upstream snapshot and configuration. Those are operator
declarations: a model-name API cannot attest loaded weights. The receipt labels
the catalog generator accordingly; embedding and reranker execution remain absent.
An attempted capture with no parsed response records `attempted_no_parsed_response`.
At least one parsed response records `parsed_responses_observed_not_inference_attestation`;
even a malformed response or abstention is only response evidence, not inference
or quality attestation. Failed requests cannot establish whether inference ran.
Record actual runtime/GPU/driver details without private hostnames or paths.
Artifact digests and supplied offline-evidence digests must be JSON strings with
64 lowercase hexadecimal characters. Unexercised offline readiness keeps its
evidence digest null. Ollama identity observations also require a string digest.
Runtime declarations and the initial capture metadata must encode as finite UTF-8
JSON before the first identity observation or model request. Invalid Unicode in
metadata therefore cannot consume all planned requests before receipt creation fails.

```console
PYTHONPATH=src python scripts/evaluate-claims.py capture \
  --backend openai --endpoint http://127.0.0.1:8000 \
  --profile portable --model recordbench-qwen35-4b \
  --runtime-profile /tmp/r1b-runtime.json --repetitions 3 \
  --output /tmp/r1b-capture.json
```

The `openai` backend means the existing local OpenAI-compatible adapter, not a
cloud service. An explicit HTTP IPv4 loopback endpoint is required. `ollama` is
also supported. The evaluator supplies a dedicated transport for both metadata
and generation: ambient proxies are disabled and every redirect is refused before
following it. A redirect aborts capture without a quality receipt. Ordinary
application transport defaults are unchanged. Identity checks surround every call,
including failures, and run again before completing the capture. Ollama checks
artifact digest; the compatible
API checks unique model ID only. Snapshots cannot exclude change and reversion
between checks. Any missing/mismatched identity aborts without a quality receipt.
The capture API itself requires matched identity snapshots from its checker and
records the method, model/artifact observations, boundary count and limitations.
A no-op checker is refused before generation. Grading also validates that identity
record and the complete runtime declaration, including the selected generator's
pinned model ID, revision and license; bypassing the CLI cannot omit these checks.
As with any injected transport, a caller
fabricating snapshot values is not independent runtime evidence.

Choose repetitions in advance (1–20). Capture records exact prompts and response
schema, raw parsed output including discarded claims/limitations, failure types,
schema-invalid responses, abstentions and timings. An abstention is counted only
when the ordinary production verifier records an abstained response. A contradictory
`answerable: false` response containing claims is rejected, even when it satisfies
the JSON schema, and is not counted as an abstention. It uses production temperature
0.1 and output-token budget; adapters do not set seeds, so reproducibility means
repeatable protocol and retained outputs, not identical stochastic answers.
Ollama uses the production 8192 context setting; compatible API context capacity
comes from the server launch evidence. Capture is single-pass: no repair, retrieval,
saved context, ingestion, browser, or supported-hardware acceptance is implied.
Each attempt separately records whether the adapter returned a parsed response.
Non-finite or unencodable parsed output remains a failed attempt with that observation
retained, without storing the unsafe raw value. Adapter parsing failures preserve
earlier completed samples and the planned population; identity and redirect boundary
failures still abort the capture.

Offline readiness remains `not_exercised` unless the operator supplies
`operator_attested` plus a SHA-256 for separate offline execution evidence.
Staged artifact inventory alone does not prove inference worked with egress
disabled. Keep generator, embedding, reranker, installed-stack and supported-device
evidence separate under [model requirements](MODELS.md) and
[release readiness](RELEASE_READINESS.md).

## Independent human grading

```console
PYTHONPATH=src python scripts/evaluate-claims.py grade-template \
  --capture /tmp/r1b-capture.json --output /tmp/r1b-grades.json
PYTHONPATH=src python scripts/evaluate-claims.py score \
  --capture /tmp/r1b-capture.json --grades /tmp/r1b-grades.json \
  --output /tmp/r1b-scored.json
```

Between commands, a reviewer reads each raw output against the frozen source and
case expectations, then fills every null grade and rationale. Use a pseudonymous
grader ID. Judge every raw claim and limitation, including duplicates and malformed
slots, without using the verifier's decision as ground truth. `answer_correct`
requires a well-formed, materially complete answer to the question with correct
meaning, attribution, qualifications and citations. All v2 questions are
answerable; abstention is an answer error. A malformed response is an answer error.
An omitted requested fact is an answer error even if its surviving claims are true.

Grades bind to the exact capture and rubric digests. Scoring refuses stale,
missing, duplicate or extra samples/claim grades and altered verifier results.
It also checks the complete recorded generation protocol and each prompt against
the frozen case and adapter settings, plus the declared model catalog and fixed
scope/acceptance fields. Generated rows require JSON objects, as both production
adapters do; arrays and scalar responses cannot become generated grading samples.
Failure rows cannot carry generated-output fields that would otherwise disappear
from human grading. Parsed-response evidence, row states, verifier outcomes and
typed aggregate counters must agree.
Execution metadata must retain its complete typed shape and a valid UTC capture
timestamp. The recorded Git revision must be available locally when grading; the
harness does not fetch it. For a capture recorded as clean, implementation hashes,
model-manifest digest and frozen-suite digest must also match that revision's
committed files. Dirty captures remain explicit
and bound to their captured implementation hashes; grading does not require the
reviewer's operating system, Python version or checkout state to match the capture.
Use the captured code revision; code-fingerprint changes require an explicit new
evaluation, not silent regrading with different verification. Hashes detect edits
and bind artifacts; they are not signatures or independent runtime attestation.

Generation metrics separately report failed attempts/all attempts, answer errors/
generated responses, unsuccessful attempts/all attempts, semantic errors/raw
graded claims and citation errors/raw graded claims. Verifier false acceptance
uses invalid raw candidates as its denominator; false rejection uses faithful,
correctly cited candidates. Semantic and citation false-acceptance subsets are
also reported. Limitations are candidates; duplicate output occurrences remain in
the denominator, but production-deduplicated material claims are marked
`duplicate_omitted` instead of retained. A separate duplicate-omission count makes
that distinction visible; the retained-occurrence false-rejection metric includes
faithful duplicates that were not retained. Empty denominators yield null rates.
The final score includes all grades and case-level verdicts. Human disagreement should receive independent
adjudication recorded in a new grade artifact, never overwrite an earlier receipt.

Real generator quality, learned retrieval, offline execution, supported hardware,
representative workload thresholds and installed acceptance remain pending until
their own evidence exists. Review all receipt text and metadata before any public
upload, then follow the publication guard and current public-alpha policy.

Identity methods are bound to the production adapter: Ollama requires tag-digest
snapshots; the compatible adapter uses model-ID snapshots with its explicit
weight-attestation limitation. Non-finite values and unpaired Unicode surrogates
from permissive JSON parsing are failed generation attempts. Artifact serialization
and UTF-8 encoding complete before writing. The complete receipt is written and
closed in a temporary file beside its destination, then installed without replacing
an existing path. A failed write or close cannot publish a partial final receipt.
Cleanup is attempted; interruption or cleanup failure can leave a private temporary
file. Existing destinations remain untouched.
